# 设计决定、机制复审与后续待办

更新：2026-10-09。分别记录用户决定、当前实现和助手建议；待办与复审项不代表全部都要实施，以实际试玩是否改善核心体验决定去留。

## 设计决定与机制复审

后续设计变化在此精简记录日期、决定来源、理由、实现状态和复审条件；完整规则更新到对应机制文档，不在此重复维护。复审条件是再次讨论的依据，不是自动恢复旧机制或增加功能的授权。

### 人口服务经营与扩张，金币跨机制流动

- **2026-10-09，用户确定；已实现**：普通炮塔与墙建造和运行不额外占人口；同日补充瞭望塔每座持续占1人、拆除释放，保留经营中的住房与生产关系，以及炮位占经营面积的实际后果。架炮附带人力、独立清理废墟用工及相关参数均已移除。边界与当前规则见 [人口职责](housing.md#人口的职责边界2026-10-09用户确定已实现)。
- **理由**：金币已让经营与防守竞争预算；资源不必全部贯穿所有机制。新增资源或联系，须说明它带来了什么已有资源无法表达、值得玩家考虑的选择。
- **助手建议的复审条件**：若实际试玩反复出现“有钱即可当晚大量补炮，提前规划失去价值”，再比较是否需要建设节奏限制；先检查现有金币加急、炮位容量与空间约束，不预设恢复人口限制。

### 取消清理用工

- **2026-10-09，用户确定；已实现**：独立清理废墟也不再占用人力，删除左上人口下的清理人数与实验参数。清理人口不恢复；人口现用于住房提供、生产与瞭望塔占用。

### 新建基价、修缮优惠与同日操作

- **2026-10-09，用户确定；已实现**：拆除即时免费，不占人口；空地新建为基价，保留原用途修缮默认50%，绝对产出相同。默认修缮回本保持原曲线，新建提高；配置参数必须在面板可见（P0）。
- **已检查**：修缮后整栋拆空不保留折扣，退款不超过对应实付；嵌炮拆补按固定格价记账，修复原先取整导致同楼少付钱的问题；跨日补建不刷新旧投入日期。
- **助手建议，本轮未新增限制**：同地块一天可多次操作，先支持纠错；只有试玩证明临时换建成了重复必做动作，才考虑建设节奏或不可撤销成本。
- **用户允许；已验证**：建瞭望塔探索后当天拆除全退，失去视野处恢复迷雾并保留暗淡地形；不得继续显示实时敌人与路线。免费侦察仍可能变成固定操作套路，这是待试玩问题，不当成资金漏洞封堵。

### 控制区连接篝火

- **2026-10-09，用户确定；已实现**：不允许拆塔后留下不连接篝火的基础控制区。建造与拆后统一要求塔落点被篝火或已连回篝火的其他塔覆盖；仅覆盖相接、整栋建筑归属不能搭桥；可先补替代连接再拆旧塔。预览标红断开区域，拒绝时无退款和状态变化；调参同步校验。
- 多个独立控制区未来均须至少有一个篝火；当前仍只有一个，暂不实现多篝火及多目标进攻。此约束解决扩张连接成本，区域是否承受威胁另行判断。

### 以后增加资源或跨机制联系

- **设计原则**：允许资源只服务单一机制，也允许跨机制流动；分类本身不是新增资源的理由。
- **记录要求**：先写明它解决的具体体验问题、相较已有资源新增的选择及理解成本。若尚无试玩证据，标为假设；不要把“让系统联系更紧密”单独作为实施依据。

## 敌源发现与永久肃清（2026-10-09，用户确定，已实现待试玩）

- 已确认探索提前发现、首次出兵自动公开、夜间炮塔肃清、永久关闭；各源兵力独立预设，消灭绝不引发其他源头增强。当晚锁定进攻保留，下一晚起停止该源出兵。
- 首轮6–10个固定源头，靠近医院整体占地/兵力/耐久更高；整栋只显示一处每拍受击值，每炮每拍只命中一次。每夜回复HP支持配置、默认0，已消灭永不恢复。默认8个据点、四种可旋转形状、每格12–30HP范围与盾牌剩余量已接入，不显示等级/首次日期/血条；整晚固定80拍、天亮撤退已接入，位置/兵力/耐久/时长待试玩复审；160拍为助手建议，尚未修改默认；受击加速暂不做，定向进攻武器用户选择后续讨论。完整规则与剩余事项见 [敌源设计](enemy-source-progression.md)。

## 瞭望塔范围成长（2026-10-09，用户提出；本轮不实现）

- 网络按当前有效基础范围重新判断；不能借建筑整栋归属扩张。范围成长是否改善推进取舍留待试玩验证。
