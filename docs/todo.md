# 设计决定、机制复审与后续待办

更新：2026-10-13。分别记录用户决定、当前实现和助手建议；待办与复审项不代表全部都要实施，以实际试玩是否改善核心体验决定去留。

## 设计决定与机制复审

后续设计变化在此精简记录日期、决定来源、理由、实现状态和复审条件；完整规则更新到对应机制文档，不在此重复维护。复审条件是再次讨论的依据，不是自动恢复旧机制或增加功能的授权。

### 人口服务经营与扩张，金币跨机制流动

- **2026-10-09，用户确定；已实现**：普通炮塔与墙建造和运行不额外占人口；同日补充瞭望塔每座持续占1人、拆除释放，保留经营中的住房与生产关系，以及炮位占经营面积的实际后果。架炮附带人力、独立清理废墟用工及相关参数均已移除。边界与当前规则见 [人口职责](housing.md#人口的职责边界2026-10-09用户确定已实现)。
- **理由**：金币已让经营与防守竞争预算；资源不必全部贯穿所有机制。新增资源或联系，须说明它带来了什么已有资源无法表达、值得玩家考虑的选择。
- **助手建议的复审条件**：若实际试玩反复出现“有钱即可当晚大量补炮，提前规划失去价值”，再比较是否需要建设节奏限制；先检查现有金币加急、炮位容量与空间约束，不预设恢复人口限制。

### 取消清理用工

- **2026-10-09，用户确定；已实现**：独立清理废墟也不再占用人力，删除左上人口下的清理人数与实验参数。清理人口不恢复；人口现用于住房提供、生产与瞭望塔占用。

### 新建基价、修缮优惠与同日操作

- **2026-10-09，用户确定；已实现**：拆除即时免费，不占人口；空地新建为基价，保留原用途修缮默认50%，绝对产出相同。默认修缮回本保持原曲线，新建提高；配置参数必须在面板可见（P0）。
- **已检查**：修缮后整栋拆空不保留折扣，退款不超过对应实付；嵌炮拆补按固定格价记账，修复原先取整导致同楼少付钱的问题；跨日补建不刷新旧投入日期。
- **助手建议，本轮未新增限制**：同地块一天可多次操作，先支持纠错；只有试玩证明临时换建成了重复必做动作，才考虑建设节奏或不可撤销成本。
- **用户允许；已验证**：建瞭望塔探索后当天拆除全退，失去视野处恢复迷雾并保留暗淡地形；不得继续显示实时敌人与路线。免费侦察仍可能变成固定操作套路，这是待试玩问题，不当成资金漏洞封堵。

### 控制区连接篝火

- **2026-10-09，用户确定；已实现**：不允许拆塔后留下不连接篝火的基础控制区。建造与拆后统一要求塔落点被篝火或已连回篝火的其他塔覆盖；仅覆盖相接、整栋建筑归属不能搭桥；可先补替代连接再拆旧塔。预览标红断开区域，拒绝时无退款和状态变化；调参同步校验。
- 多个独立控制区未来均须至少有一个篝火；用户提出新篝火应提供独立网络、较大初始控制与远端经营优势，并承受新区域夜袭。当前仍只有一个，暂不实现多篝火及多目标进攻；最大服务距离60格是候选值，不能仅由160拍反推为确定规则。目标锁定、兵力不补偿与局部失守均须保持清楚，详见 [日夜节奏与区域篝火](GDD.md#游戏日节奏与区域篝火2026-10-10)。

### 以后增加资源或跨机制联系

- **设计原则**：允许资源只服务单一机制，也允许跨机制流动；分类本身不是新增资源的理由。
- **记录要求**：先写明它解决的具体体验问题、相较已有资源新增的选择及理解成本。若尚无试玩证据，标为假设；不要把“让系统联系更紧密”单独作为实施依据。

## 敌源发现与永久肃清（2026-10-09，用户确定，已实现待试玩）

- 已确认探索提前发现、首次出兵自动公开、夜间炮塔肃清、永久关闭；各源兵力独立预设，消灭绝不引发其他源头增强。当晚锁定进攻保留，下一晚起停止该源出兵。
- 首轮6–10个固定源头，靠近医院整体占地/兵力/耐久更高；整栋只显示一处每拍受击值，每炮每拍只命中一次。每夜回复HP支持配置、默认0，已消灭永不恢复。默认8个据点、四种可旋转形状、每格12–30HP范围与盾牌剩余量已接入，不显示等级/首次日期/血条；整晚默认160拍、天亮撤退已接入；大按钮底部仅进度百分比；清源保留已出场进攻，未出场批次立即阻止、不计击杀不发钱，原定预告保留灰色—与源头✓。夜末有清源则加速逐拍，全部批次已出生/被阻止且无敌人/可清源才略过空闲。位置/兵力/耐久/时长待试玩复审；受击加速暂不做，定向进攻武器用户选择后续讨论。完整规则与剩余事项见 [敌源设计](enemy-source-progression.md)。

## 瞭望塔范围成长（2026-10-09，用户提出；本轮不实现）

### 迁移方向（用户确定，2026-10-12；俯视逐步接入）

- 直接在现有主游戏逐类替换3D模型，沿用当前地图生成、seed、地块及完整十五晚流程；不另建地图、独立三天实验或另一套游戏规则。
- 先固定正交俯视，保留现有格子操作、平移和缩放；左右栏布局、组件与信息位置不变。控制、探索记忆、安全判断、敌源、寻路、经济、炮位及战斗结算继续读取现有规则。
- 俯视阶段沿用现有云雾表现及S0–S3权限、S01/S12/S23距离和敌人渐隐；等接入斜视再分析云雾的空间适配，不提前做体积云或新的视野系统。
- 后续先尝试固定斜视，再尝试自由视角；用户提出左右栏的任何操作先返回俯视。回正保持观察中心和接近的缩放，不跳回起点；具体触发细则见下方待确认项。
- 用户希望路灯保留真实光源。照明与阴影分别处理，不因担心性能直接取消路灯照明；具体预算由现有地图实测决定。

### 分步替换计划（2026-10-12，用户确认顺序；实施中）

各步都在主游戏原地图与完整流程中验收，可以渐进混用尚未替换的2D对象；不以额外实验场景或缩短流程作为前置条件。

**执行顺序与提交（用户确定）**：先适配手头已有模型，再在真实地图中补缺失资产；不等墙/门/敌人资产齐全才接入。先提交本计划，之后每个可用步骤实际验证后单独commit；提交不包含推送或发布。

| 顺序 | 工作内容 | 验收重点 |
|---|---|---|
| 1：俯视底层与建筑（已接入） | 在现有viewport加入Three.js城市层，将地形/建筑与Canvas云雾/信息绘制分开；相机对齐现有格子。先替换少量建筑及同楼废墟，再扩大用途/尺寸覆盖，模型按地块稳定选择 | 同一seed、地块位置、尺寸与点击格一致；建造/恢复/拆除即时对应真实状态，未替换对象仍可正常使用；平移缩放不使雾和模型错位 |
| 2：真实设施（已接入并适配尺度） | 按现有格子替换近远炮、瞭望塔、墙、篝火与已揭露敌源；炮塔按屋面高度落位；墙按相邻墙/建筑连接、孤立段横跨道路，HP归零留低残骸和缺口 | 建造资格、炮位容量、费用、控制边界及源头占地不变；交战、暂停、重试和重开正常，未知敌源不因加载模型而暴露 |
| 3：昼夜与运营照明（已接入） | 共用模型/色板，读取真实建设和运营状态显示窗户、屋顶暖灯、路灯与光池；道路承接光照，少量杂物作为装饰随状态变化 | 灯光随现有长按入夜/日出进度同步，取消长按一起回退；控制、安全和运营保持区别，灯光不代替准确控制边界 |
| 4：事件动效（已接入） | 接篝火/车辆火焰、控制边界外探照灯和真实开火；从预览复用形态，移除自动试射与独立演示计时 | 暂停/后台/重试/对象移除时状态正确，无目标不演示开火；伤害与时序不被弹迹改变，特效不透露隐藏敌情 |
| 4之后：补齐真实地图资产（已接入） | 墙连接/缺口、米制普通敌群与3×3篝火广场已接入；敌源残骸、已知宿主废墟与路缘垃圾/瓦砾已接入；修缮/拆除及破墙/清源短过渡已接入，按完成对象分别提交 | 墙格封堵与归零通行明确，敌群成员数/HP和合流规则保留；不为资产制作增加新玩法 |
| 5：固定斜视（已接入） | 增加固定斜视和操作回俯视，适配拾取、屋顶炮位、建筑遮挡、云雾与屏幕信息位置 | 回正后落点准确；未知楼顶/源头不穿雾暴露，可见敌人/HP/控制边界可读 |
| 6：自由视角（已接入） | 固定斜视可用后尝试旋转/角度变化，保留操作回俯视与当前观察中心 | 视角操作不与建造、右键取消和平移冲突；在现有地图正常缩放及全图下检查阅读与性能 |

**统一完善（2026-10-13）**：路灯现靠建筑侧路缘、灯臂朝道路，约7.5m高，光源跟随灯头，沿道路铺暖光池；每栋每侧最多一个候选，按30m间距去重，不落在未控/隐藏/被墙塔占用道路。大面积静态灯具已按材质合并，真实路灯固定光源池默认24盏，按观察中心及有限照射范围筛选，位置更换渐变；0–64预算在config/实验台同步，预算外保留灯罩与地面暖光。控制区内暂保留燃烧车辆；车辆的生成条件、消除时机、密度，以及配套动画/音效后续一起调整，当前装饰消除规则不代表最终设计。

### 俯视接入与规则边界（实现建议）

- Three.js城市层与Canvas叠加层共用地图坐标、视口大小、设备像素比及平移缩放。俯视仍可用现有屏幕到格子的换算；云雾覆盖城市后再画规则允许的战术信息，不让两层各自控制镜头。
- 将预览中必要的模型装载、状态外观和动效逻辑取出适配主游戏；不直接导入绑定选型页DOM和演示状态的整份脚本，也不为迁移建设通用框架。
- 建筑物理footprint与经营面积分别读取现有模型；炮位占经营格不能误缩整栋楼。装饰不得越过占地造成阻路误导，破损/完好沿用同楼身份，医院等特殊对象保持识别。模型几何不参与新的寻路或碰撞规则。
- 未探索城区沿用当前低细节轮廓，不因换成GLB暴露用途、窗户灯光、敌源或阴影情报；敌人实体、HP和弹迹先通过现有可见性判断，敌源局部揭雾沿用已有规则。
- 当前对敌炮火为每拍射程覆盖累计伤害，清源为炮塔空闲时按现有计划攻击。开火表现可以补充炮塔来源/目标信息，但不得为了单条弹道改成单目标伤害、弹道碰撞或新的锁敌优先级。
- 战斗动效读取现有暂停和逐拍插值，环境云纹沿用现有时间；昼夜光照读取与页面/按钮相同的过渡进度，配色预演不提前修改视野和战斗阶段。

### 路灯光源与性能（用户偏好已确认，具体策略待实测）

- 建议起步方案：当前画面需要的路灯保留真实光源，叠柔和地面光池；路灯默认不投独立阴影，窗户/屋顶以发光材质为主，太阳保留阴影。无独立阴影可能有局部透光感，先在俯视中检查。
- 有限照射范围配合灯光筛选：按照射范围与可见城区是否相交启用，屏幕外但照得到画面内的灯保留；白天、未恢复及不可能影响当前画面的灯退出计算。缩短光源distance本身不等于自动剔除灯光。
- 正常视角优先保留真实路面/墙面照明；全图视角若实测需要，可减少参与照明的灯，保留灯罩、窗户及道路暖光，平移/缩放时渐变避免跳亮。本轮实测后采用默认24盏固定真实路灯池，0–64在实验台可调；并合并所有静态路灯几何，保持光池和真实照明区分。
- 太阳静态阴影在建拆或光照方向变化时更新；未来少量重点路灯如需阴影，再限制分辨率、范围和投影对象。移动探照灯如投阴影须按移动更新，不能长期复用旧结果。
- 先在现有地图近景、正常视角、全图，以及后期大面积恢复/多炮交战下实测；实测有瓶颈再考虑固定光源预算、合并装饰或更复杂渲染，不提前搭延迟渲染/大规模灯光框架。新增可配置参数须同步config、实验台、校验和运行逻辑。
- 技术依据：[Three.js阴影说明](https://threejs.org/manual/pages/shadows.html)、[PointLight距离](https://threejs.org/docs/pages/PointLight.html)、[LightShadow按需更新](https://threejs.org/docs/pages/LightShadow.html)。
