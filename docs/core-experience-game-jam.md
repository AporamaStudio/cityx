# CityX 核心体验与 Game Jam 命题

日期：2026-09-30。

本文将 CityX 的核心愿景提炼为一个可用于小规模原型验证的 Game Jam 命题。核心体验的表述、Jam 主题与验证规模来自本次讨论中的助手建议，供后续试玩和取舍使用；不把它们视为新增的已批准机制或开发任务。

## 1. 核心愿景

> 从一小块立足之地开始，亲手把危险、失序的城市，逐步变成可以生活、生产、值得守护的家园。昨天的前线，成为今天的后方。

玩家的行动应在地图上留下可以看见、使用和继续积累的成果。随着安全空间扩大，曾经需要亲自应对的地方逐渐稳定下来，玩家能够把注意力移向更远处。

最希望玩家产生的一句话是：

> “这里以前很危险，现在我可以放心把它交给城市，去更远的地方了。”

## 2. 三种相互衔接的满足感

- **收复的成就感**：曾经无法立足的地方，现在可以建设、使用，成为下一步行动的起点。
- **建设的成长感**：收复的土地产生实际价值，玩家的安排让城市更有能力；建设后尽快出现清楚的变化或收益反馈。
- **守住成果的满足感**：敌人来袭时，之前的经营与布防发挥作用。守住之后，留下可以继续积累的成果。

三者形成一条体验链：

**站稳脚跟 → 向外扩张 → 建起有用的东西 → 守住它 → 用它支持下一次扩张。**

安全感的积累是这条体验链的重要部分。旧区域逐渐成为可靠后方，新增领土带来新的建设机会和防守责任。组织与领土扩大时，玩家不必同比增加对每一处旧区域的重复操作。

## 3. Game Jam 命题

### 《让昨天的前线，成为明天的家园》

*Yesterday’s Frontline, Tomorrow’s Home*

征题文案：

> 你拥有的，起初只是危险世界里的一小块立足之地。
>
> 请制作一个游戏，让玩家通过自己的行动，把危险之地变成能够支持生活与继续前进的家园。
>
> 新获得的空间应带来新的可能，也带来需要承担的风险。玩家必须设法守住自己的改变，并依靠这些成果走得更远。
>
> 游戏结束时，希望玩家能指着某个地方说：“这里以前很危险，是我让它变成了现在这样。”

这个命题保留体验目标，让实现机制保持开放。现代城市、僵尸、炮台与昼夜循环都可以承载它；森林复苏、太空殖民或海底基地修复等题材，也可以回应同一种感受。

## 4. 三个体验要求

| 体验要求 | 玩家应能感受到的变化 |
| --- | --- |
| 空间发生有意义的转变 | “这片地方现在能做以前做不了的事了。” |
| 建设成果帮助继续推进 | “因为刚才的经营，我现在有能力再往外走一步。” |
| 成果经历一次压力考验 | “我刚才的选择确实帮我守住了这里。” |

地图上的颜色、边界和数字应帮助表达这些变化。体验是否成立，最终要看玩家能否在实际游玩中理解并在意这些成果。

## 5. CityX 的小规模验证建议

建议先做一个 **10～15 分钟的小体验**，让玩家完整经历一次上述体验链。这个时长是单次验证体验的建议，不替代已有的“完整游戏日约五分钟”方向，也不规定 Jam 的开发期限。

地图只需足以让一个地方从前线变成后方，并提供下一次扩张的机会。经营与防守规则可以采用成熟方案，也可以在试玩后删换；无需先做完整城市、复杂生产链或长期成长系统。

试玩时重点观察和询问：

- 玩家有没有主动想要“再拿下一块地方”？
- 守住之后，有没有感觉自己真正留下了成果？
- 玩家能否指出一项建设，说明它怎样帮助了防守或下一次扩张？
- 回看最初的立足点时，有没有觉得“我已经走出去这么远了”？

这些问题用于定位体验缺口，不是通过代码检查就能满足的验收项。若体验不成立，应优先调整或删换当前机制，再次试玩。

## 6. 与当前项目方向的关系

已有明确方向包括：保留城市收复与安全区扩张；经营与扩张是主要体验，塔防提供压力并检验经营；采用非即时建设／经营／扩张与可暂停即时防守两个操作阶段；重视建设后的即时反馈；允许使用成熟机制并控制规模。

本文不要求恢复旧 Godot 原型的远征、搜打撤或四阶段流程，也不指定固定或移动炮台、敌人合并、具体经济公式等实现方式。

截至本文编写时，新 Web 原型已经包含三晚防守、前哨扩张与失守、付费修复和击杀收入；经营收入设施尚未实现。当前控制范围表示建设权限，敌人可以进入其中，不能将它直接等同于愿景中的稳定安全区。原型已有首轮试玩反馈，尚未被双方认可成功。

本文提出的主题用于帮助判断下一次实验是否更接近核心体验，不自动扩展当前实现范围。
