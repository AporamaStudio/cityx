# 文明区、篝火与城市复兴

更新：2026-10-18。**分步实施中：第1至5步已接入，多篝火技术检查完成，玩法待用户试玩。** 本文承载文明区与篝火的机制、体验目标及实施顺序；GDD、项目简述只保留摘要与入口。

设计依据为本轮讨论与用户对新版总览的澄清。外部《CityX 原型设计总览与当前规则》不能整体视为实现规格：其中“视野＝控制”、银行额度60、地面炮塔受击等表述，不替代项目已有决定。

## 1. 已确认的职责与范围

| 对象 | 职责 | 边界 |
|---|---|---|
| 瞭望塔 | 同时提供控制与实时视野，推进建设和观察 | 视野向控制区外延伸；看到不等于可以建设 |
| 篝火 | 提供文明覆盖，使受控城区具备恢复生活的条件 | 新机制中不再直接提供控制面积；文明能力不与炮塔火力来源绑定 |
| 墙、炮塔 | 阻挡和消灭进攻，保护聚居点与恢复成果 | 不定义文明范围；军事设施可以部署在文明区外的合法受控位置 |

- 对玩家统一称“文明区”；本轮讨论中的“安全区”指同一运营概念，不保证敌人无法进入。
- 已探索记忆、当前视野、控制权限、文明运营分别判断。保留现有迷雾的信息边界、昼夜视野与已知POI/敌源揭示规则，不因新增文明区合并这些系统。
- 基础控制由有效瞭望塔网络提供。物理建筑继续碰到基础控制至少一格即整栋归属，且不向相邻建筑或外侧道路传播；连续地面逐格控制。墙、瞭望塔继续使用基础地面权限，炮位继续使用整栋受控建筑权限。
- 瞭望塔仍须通过当前有效塔网连接至存活篝火。篝火作为网络根节点与“输出控制面积”是两件事；去掉后者后，初始塔与根节点的连接办法必须同步解决。
- 文明覆盖是篝火的局部空间范围，不是全局面积容量。实际文明地面＝当前控制地面与所有存活篝火文明覆盖的并集相交。重叠不重复提供运营收益，不要求玩家分配城区容量。
- 不要求围墙闭合，不增加内部清敌判定作为文明覆盖的额外条件；覆盖本身不消灭敌人或敌源、不造成伤害、不重选进攻目标、不修改物理通行。已有清源与防守规则继续发挥作用。
- 取消检查站与独立驻防站，不实施面积驻防容量、比例减产或容量不足后的区域分配。驻防小队是未来候选，不是文明区成立的前提。

## 2. 建筑结构、用途与文明运营

物理建筑结构只区分废墟、完好；用途、升级、工作人员与当前运营另行判断。拆空后是可通行空地，不属于这两类建筑状态。

| 区域 | 废墟 | 完好建筑 |
|---|---|---|
| 未控制 | 保留结构，不可修复 | 可以存在，不接入玩家城市 |
| 受控但未文明 | 可以按现有用途、资源条件修复 | 保留结构与升级，尚未正常生活/经营 |
| 文明区 | 可以修复，不自动变完好 | 满足用工及对应设施条件后，正常运营 |

- “受控才能修复”也包含文明区。修复与接入可以按玩家选择的顺序发生，不新增跨天等待。
- 修复成功立即反馈结构恢复；接入后立即反馈正常运营与生活，经济仍沿既有夜末入口结算，避免重复入账。
- 新住房首次接入与既有居民暂时失去文明支持不能混为一谈。失去覆盖不把楼变回废墟，不抹除升级或直接删除居民；首次入住记录、暂时安置、用工保留与恢复细则须在人口接入时明确。
- 建筑整体文明资格不能直接从逐格交集推断，也不默认照搬“碰一格整栋控制”。必须确定一条可预览、各用途一致的整栋判定规则，见第5节。
- 普通建筑继续不受敌人主动攻击；新机制不顺带加入逐栋HP或破坏系统。炮位、经营用途变化与实际建筑建拆对通行的影响，沿用现有规则。
- 银行恢复与银行运营分开：受控时可以修复，正常金融能力还须文明资格及人员条件；停业保留恢复、升级和既有债务，不能形成免息或立即追缴。医院是否须文明运营才计入通关，尚未确定，不自动改动现有胜利条件。

## 3. 安全感与文明复兴的体验目标

玩家应能分别感受到：**推进控制，取得行动空间；恢复建筑，留下稳定投资；接入文明，让空间重新被使用；守住防线，让生活持续。**

### 两次清晰的恢复反馈

1. 修复：楼体缺口、瓦砾与失养状态转为完好结构；尚未运营时保持安静，不提前点亮运营灯光。
2. 接入：白天出现少量有目的的工作、居住与互动，夜晚出现窗灯、街灯与营地照明。建筑类型与真实运营决定表现，不能只按文明蒙版把所有废墟点亮。

优先复用已有废弃/修复/接通资产与照明表现，补少量生活活动。居民表现不意味着新增可指挥、可受击的人口单位，不为制造热闹而先做全城人口模拟。

### 安全感的三个来源

- 成果稳定：修复与升级保留；失去支持会影响运营，但不会凭空撤销玩家投资。
- 威胁可理解：进攻提前锁定、路线可读、危险与失败原因明确，玩家能判断自己的防线为何有效。
- 生活持续：同一片城区守过数晚、附近敌源被永久肃清，前线逐渐变为后方；人员活动、灯光与声音强化这段变化。

目标画面是“外侧防线交战，后方住宅仍有人生活”。文明区内仍可能经过敌人，不用能量屏障或免伤表现暗示绝对保护；永久减压由现有敌源肃清规则提供，不给旧城区补偿性增兵。

### 叙事与世界观边界

篝火是聚居点的可见核心，支撑人类恢复生活所需的环境。净化/环境维持的具体原理、灾难来源与敌方动机仍可讨论，不冻结完整世界观；暂不宣称文明范围对敌人致命，也不因此加入伤害、减速或削弱效果。

炮塔的武器与火力独立成立，无须由篝火供能。篝火、瞭望塔与防线的不同职责应通过玩家行为和恢复后的城市说明，不依赖长篇解释。

## 4. 空间表现与交互

- 保留已清晰的蓝色控制边界，尝试增加一条可辨认的文明边界；是否采用暖色、两线重合怎样呈现，通过三视角与远中近景实看决定，不预先否决第二条线。
- 实际文明区与篝火理论覆盖须可区分。选址/升级时可查看将激活的建筑、尚未受控的覆盖部分与真实范围，未知区域仍遵守迷雾，不借预览泄露POI或用途。
- 日常运营、照明与少量活动共同表达文明，边界线负责准确规划。未运营的完好楼与文明区内废墟仍须容易区分。
- 报价、灰显可选工具、资源不足项、顶栏静态原因与点击拒绝共用现有P0规则；受控但未文明时允许修复，不把“暂未运营”误报成“不可施工”。
- 新增玩法/视觉参数同时接入config、对应实验面板、校验、预览、应用/取消/默认；金币与人口保持整数。范围更新随状态变化重算，镜头移动复用；如涉及性能优化，按既有P0记录实测与副作用。

## 5. 开始实现前须明确的最小选择

下表是实施依赖，建议项不等于已冻结数值或完整规则。不因此扩展成新的系统。

| 问题 | 当前建议与边界 |
|---|---|
| 初始控制从哪里来 | 初始营地配套瞭望塔，避免“没控制不能建塔、没塔没控制”；具体落点、是否占初始工人、起步预算与教学开放须一起处理，不能只把旧篝火半径设为0 |
| 网络怎样连到无控制面积的篝火 | 明确根部塔接入条件，保留动态联网、禁止建筑归属搭桥及现有防孤岛约束；根节点身份不产生隐形控制半径 |
| 篝火是否保留自身观察能力 | 本轮未要求取消；把旧控制输出迁移为文明输出时，单独核查现有火光视野，不能随手删除或把文明范围当成实时视野 |
| 文明范围形状与初值 | 10格仅为外部文档举例；形状、起步范围、升级费用与增量按60格原型的实际建筑布局确定，并在配置/面板开放 |
| 整栋建筑如何接入 | 建议比较统一地块中心判定，避免大POI只擦边一格就远距离激活；不引入入口管理，不让半栋楼运营。最终规则须同步建筑预览与边界表现 |
| 未运营建筑怎样占人、住房何时入住 | 明确预留/实际用工、首次接入人数、失去支持后的保留与重连；避免重复入住、人口负数及停业释放工人后双重使用。初始先遣队不依赖尚未接入的住房 |
| 多篝火的建造与失守 | 控制内合法可达落点、费用/用工、根部塔配套、每座HP和攻击区、重叠接替及整局失败规则需成套确定。建议单座失守造成局部损失，尚不能视为已实现 |

## 6. 实施顺序（第1至5步已接入，第6步区分技术检查与玩法试玩）

### 第一步：单篝火范围解耦与初始控制

先完成第5节中单篝火必需的选择。将控制、文明覆盖、观察能力分别计算；把篝火直接提供的控制迁移至起步瞭望塔，接好网络根部与起步教学。继续沿用建筑原子控制、基础地面权限与独立探索记忆。

验收：控制外可观察不可施工；受控但未文明可施工；白天转夜晚不缩小控制或文明权限；初始局无需额外资源即可开始既有建设循环。

### 第二步：建筑运营、人口与经济接入

统一建筑文明资格和“完好且可运营”判断，接入生产、住房与银行。修复许可仍读控制，运营读取文明与人员；处理首次入住、停业保留、重连、拆改依赖和整数资源预览。核查预计收入、实际夜末收入、银行停业及债务规则共用结果。

验收：前线修复只改变结构，接入才激活作用；失去支持不删楼/升级/居民；重连不重复发人口或重新收费；夜末与重试不重复入账。医院通关条件只按明确批准的方案调整。

### 第三步：文明边界与最小生活反馈

在现有主原型接入第二条边界、篝火覆盖/经营激活预览及手册短句，三种视角一致。复用已有建筑状态与灯光，在一片城区补少量白天活动，形成可亲手经历的“废弃—修复—接通”变化。

验收：玩家能辨认施工权限与运营范围；白天能看出接通，夜晚能看出生活；未知信息不泄露，战斗路线/HP仍可读。做到这里先实际玩一段完整日夜，不等待多篝火全部完成。

### 第四步：单篝火文明范围升级

先只加入扩文明范围这一项成长，选址/升级显示将激活的已知建筑与真实报价；不同时加入人口、每日金币、自带武器或完整升级树。升级不扩瞭望塔控制、不改变已锁定进攻。

验收：覆盖增长立即产生可理解的经营与生活变化；控制外仍不能运营；取消不收费；参数、钱包、人口与收益预览一致。

### 第五步：第二篝火与完整防守闭环

把单一火光引用迁移为有稳定身份的篝火集合，贯通每座HP、攻击区域、控制网络根节点、文明并集、修复、告警、快照、重试与结算。建造仍遵守明确的地面与控制规则，不能在不可通行楼内制造不可接近目标。

所有据点共享资源与夜晚时钟。进攻生成时锁定来源、目标与路线；当天新建不改变今晚题目，后续才纳入目标选择，不复制兵力或补偿其他敌源。单座失守、重叠文明接替、网络转接与整局失败规则必须随本步一起闭环，不能只画多个图标或叠加范围。

验收：第二篝火支持新城区；每批进攻只伤害其锁定目标；两火重叠不重复收益；失守和重试准确恢复状态；检查末批出生与路线行程能否在160拍内到达。

### 第六步：实际试玩与范围复审

在60格主原型体验从第一片城区到第二片城区：玩家是否主动想恢复远处建筑，是否理解为何未运营，点燃篝火是否有明显满足，升级与新建是否都有选择价值，夜晚是否需要频繁救火或切镜头。

玩法验证与技术检查分别记录；按实际问题调整范围、费用、起步资源和表现。256格大城只承担既有尺度/性能实验，不让十小时城市、三势力、驻防小队或完整生活模拟成为本轮前置条件。

## 7. 当前实现入口与不随本轮回退的规则

当前运行版已支持多篝火：控制由联网瞭望塔提供，篝火提供文明覆盖。住房首次接通后入住、生产与银行接通后运营。单座熄灭局部停业，全部熄灭才失败。医院目标仍为修复并受控，不顺带增加文明覆盖要求。

- `src/model.js`：基础/最终控制、联网、建设许可、人口与经营、银行、火光HP、目标/路线、快照和夜末结算。现有`inGroundControl`、`productionControlled`、`productionActive`等语义需逐项拆开，不能全局把控制检查替换为文明检查。
- `src/visibility.js`及现有视野入口：保持探索与观察独立，核查旧火光控制迁移对揭示与缓存的影响。
- `src/app.js`、`src/control-border.js`、`style.css`：范围预览、边界、工具、资源反馈与手册；`src/city-3d.js`承载对应建筑状态、生活及照明表现。
- `src/config.js`、实验控件、验证与现有测试：新参数双向暴露，覆盖起步、停业/重连、重叠、失守、重试与夜末结算。

现有银行每座基础额度100、独立三选一、存贷整数取整，建筑炮位不受击、废墟原用途修缮优惠与拆空换建、永久清源不补偿增兵，以及现有日夜战斗节拍继续保留。医院目标、长期城市完成条件、可破坏地面炮与居民军事化均不由本文顺带改造。

## 实施记录

- 文明Step1：初始营地同格配套瞭望设施免费保留、不占额外人力；其控制半径沿用原初始参数，常规塔使用各自半径。篝火不再输出控制，联网只由有效塔传播。文明半径默认10格并同步玩法面板；建筑按地块中心整栋判断。起步设施会在第3步用独立位置表现。

- 文明Step2：建筑表现统一为废墟、已修复未接通、已修复且接通。生产/银行须接通才生效；住房首次接通记录入住，暂停覆盖保留已入住居民与预留用工，重连接入不重复发人口。医院胜利资格仍按原规则，不顺带改变目标。

- 文明Step3：三视角增加暖色短虚线文明边界，重合处保留蓝线可读；边界按整栋接入绕楼。既有模型、运营窗灯/街灯和街景读取真实文明资格，白天已接通院落有米制少量往来人物（可关闭，不参与人口/战斗）；营地配套塔在同格内与火堆分开摆放。浏览器实测先修住房人口保持6、文明接通后变8，斜视边界与生活表现无运行错误。

- 文明Step4：右侧火光栏新增升级，悬停预览文明扩展、将接通建筑与资源增减，点击才扣款。默认基础费40×本次级数、半径每级+4、最多3次，均在玩法面板/config开放；不增控制、HP或火力。浏览器验证500→460金币、半径10→14，下一次费用80。

- 文明Step5：第3天可在完整基础控制、已探索且无障碍/设施的3×3地面新建篝火，默认80金币、不额外占人、不赠瞭望塔。每座独立HP、等级、修复与升级，右栏可切换；文明取并集不重复收益。新篝火可作为现有瞭望网络根部，但自身仍不输出控制。当天进攻不变，下一晚起按可达最短路选存活火光，平局按格ID；目标和路线随后锁定，不复制兵力。
